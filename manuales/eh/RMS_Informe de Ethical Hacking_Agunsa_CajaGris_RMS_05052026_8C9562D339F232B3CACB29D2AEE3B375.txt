Metodología de Trabajo
Para la categorización y registro de vulnerabilidades detectadas, se utiliza la metodología
OWASP (Open Worldwide Application Security Project), la cual es aplicada tomando en cuenta
su versión más actualizada para cada tipo de revisión o pentesting realizado (Web, Mobile,
API). A su vez, para complementar esto y dar un enfoque más específico, también se utilizan
las definiciones descritas en el CWE (Common Weakness Enumeration). Estos son

vulnerabilidades informáticas, los cuales permiten dar un mayor entendimiento de las
mismas.
Criterios de clasificación del riesgo
Para realizar la clasificación y puntuación de las vulnerabilidades detectadas, se utiliza el
sistema de puntuación CVSS v4.0 (Common Vulnerability Scoring System), éste es un
framework abierto que permite capturar las principales características de una vulnerabilidad
y genera un valor numérico que refleja el nivel de severidad, así como también una
representación textual del score, esto se traduce a una representación cualitativa (crítico,
alto, medio y bajo) que permitirá ayudar al equipo técnico a priorizar el proceso de gestión de
vulnerabilidades. Los valores evaluados se muestran a continuación:

Referencias: https://www.first.org/cvss/calculator/4.0 Beneficios del CVSS:
A. Alineado con la norma PCI DSS.
B. Estandariza la calificación de la vulnerabilidad.
C. Prioriza el riesgo.
D. Considera el impacto directo sobre el objetivo, así como el impacto subsecuente en otros

C01: Exposición de Credenciales en Texto Claro en API de Parámetros contiene
secretos Críticos Comprometidos (SMTP, AWS IAM)
Descripción: Se ha identificado que la aplicación se puede invocar a un endpoint de
parámetros de configuración (/api/parametros) devuelve en texto plano, sin cifrado y sin
protección adicional un conjunto de credenciales altamente sensibles almacenadas en la
tabla de parámetros de configuración del sistema. Entre los secretos expuestos se
identificaron: credenciales SMTP de Gmail con capacidad de envío masivo de correo, claves
de acceso AWS IAM con permisos de lectura y escritura sobre el bucket S3 develop-agunsa
(región us-east-1), credenciales de conexión a ActiveMQ (broker de mensajería), y API keys de
UptimeRobot. Todos estos secretos fueron verificados como funcionales durante el pentest
autorizado.
Con estas credenciales es posible acceso directo al smtp para envio de correo, al bucket S3
develop-agunsa (región us-east-1) y se confirmó que utilizando estas credenciales se logró
acceso con permisos de lectura y escritura al bucket develop-agunsa (región us-east-1).

Conclusiones
En el marco de las pruebas de seguridad realizadas sobre el Portal RMS, se identificaron 5
vulnerabilidades que podrían comprometer la seguridad de la aplicación y la protección de la
información procesada.
Los hallazgos detectados se relacionan principalmente con:
•
•
•
•
•

Exposición de Credenciales en Texto Claro en API de Parámetros contiene secretos
Críticos Comprometidos (SMTP, AWS IAM).
Apropiación de cuenta completa (ATO) en cualquier cuenta mediante cadena de
vulnerabilidades.
Stored XSS (Cross-Site Scripting Almacenado) al ingresar o actualizar datos.
Ausencia de Rate Limiting en Operaciones CRUD.
Mal manejo de errores permite ubicar rutas internas.

Estas vulnerabilidades podrían permitir la alteración de datos, el acceso indebido a
información sensible o la enumeración de recursos internos, impactando la confidencialidad,
integridad y disponibilidad del sistema.
Se recomienda implementar las medidas de mitigación descritas en el presente informe y
realizar las validaciones técnicas correspondientes una vez aplicadas. Asimismo, se sugiere
mantener coordinación con el equipo de desarrollo para verificar la correcta implementación
de los controles y ejecutar una revalidación posterior que confirme la remediación efectiva de
los hallazgos.
